# google-pubsub

A stateless client for Google Cloud Pub/Sub's REST API, over the user's own
Google connection (the pubsub scope), in the style of `integrations/cloudflare`:
it knows nothing about who calls or why. First consumer: Gmail push
(`apps/mail/providers/gmail`, "instant updates").

- **`core`** — `PUBSUB_SCOPES` (`https://www.googleapis.com/auth/pubsub`) and
  the errors: `PubSubApiError` (status, Google's ErrorInfo reason or status,
  message, and `activationUrl` / `serviceDisabled` when the project has the
  Pub/Sub API turned off), `PubSubUnreachableError`, `PubSubResponseShapeError`.
- **`server`** —
  - `getPubSubToken({ refused? })` — a pubsub-scoped token through
    auth/central (`needsConsent` when the scope is not granted).
  - `createPubSubClient({ accessToken, fetch? })` — one HTTP request per
    call, no retry (a setup is a click; a consumer owns its reconnect); a 401
    is sent once more with a token asked past the refused one:
    `ensureTopic`, `grantOnTopic(topic, role, member)` (IAM read-modify-write
    under the etag), `ensureSubscription(name, { topic, ackDeadlineSeconds,
    messageRetention, expireAfterIdle })` (a pull subscription; a same-named
    one on another topic is refused), `deleteSubscription`, `pull(name, {
    maxMessages, signal })` (a **held** pull: Pub/Sub answers when messages
    arrive; `gone` on 404) and `acknowledge`. `topicName` /
    `subscriptionName` spell the resource names, `messageText` decodes data.
- **`web`** — `usePubSubAccess()` (granted / missing / disconnected, a read)
  and `PubSubGrantButton` (the scope-grant popup), so a consumer never
  imports auth.

**Why REST pulls, not StreamingPull.** StreamingPull is gRPC: the official
client (`@google-cloud/pubsub` over `@grpc/grpc-js` and google-auth-library)
is a heavy dependency for one stream, and wants service-account style auth.
A REST pull without `returnImmediately` is held open by Pub/Sub until a
message is published, so a consumer that issues them back to back hears a
notification within one round trip — the same latency, a plain `fetch`.

## Plugin reference

- Description: The Pub/Sub scope on the shared Google connection, web half: usePubSubAccess() (granted / missing / disconnected, as a read) and PubSubGrantButton (the scope-grant popup), so a consumer never imports auth nor names the scope.
