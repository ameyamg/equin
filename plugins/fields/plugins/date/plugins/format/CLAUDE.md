# format

How the app writes a date or a time. Three settings (Settings → Config,
`date-format`): **Clock** (browser / 12-hour / 24-hour), **Date order** for a
date spelled with a month name (browser / month first / day first) and
**Numeric dates** for an all-digit date (year first `2026-11-27` by default,
browser, month first, day first).

- `useDateFormatter()` (web, live), `serverDateFormatter()` (server), or a
  `DateFormatter` handed to a pure `core/` function (a data-view grouping gets
  the user's as `GroupingPlanContext.format`); tests build one with
  `createDateFormatter(prefs)` from `core/testing`.
- Its options name WHAT to show (seconds, weekday, year, zone) — never a
  locale or an hour cycle, so no caller can write another clock.
- The lint rule `date-format/no-raw-date-format` refuses the platform
  formatters elsewhere. Code that computes with dates (zone arithmetic, a fixed
  machine format, an LLM prompt) declares a sanctioned exemption.
- A plugin below `config_v2` in the graph (log-channels) cannot import this
  one: it takes the formatter as a prop from its caller.
- In a jsdom suite `useDateFormatter()` answers the default settings: the
  shared setup (`test/setup.ts`) mocks it once, since a suite renders with no
  config registration (where the real read throws, as it must in the app).
