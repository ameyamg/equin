# media

The **media** field type: uploaded files — images, videos, anything a field's
`accept` admits — held as `MediaRef[]`, in the order a surface shows them.
The value is the refs, never the bytes: each ref names an attachment
(`infra/attachments`) and carries what a surface needs to draw it without
fetching it first (`mime`, `filename`, `size`, and — read in the browser when
cheap — `width` / `height` / `durationMs`).

## Core

- `MediaRefSchema` / `MediaRef`, `mediaFieldType` (id `"media"`) and
  `mediaIdentity` (kind `visual`, no `coerce`: a set of files has no sortable
  scalar).
- `mediaField({ label, description?, accept, max?, maxBytes? })` — the
  factory. Default `[]`. The schema is the ref list (capped at `max`, else a
  `wholeList`) refined to unique attachment ids. `maxBytes` bounds each file
  and is sent with each upload; absent, the upload's 20 MB default — a video
  field declares more (up to `ATTACHMENT_MAX_BYTES`, which the server
  enforces). Core does not import `infra/attachments`: that closes a cycle
  through the storage capability loader. A bad `max` / `maxBytes` throws at
  declaration. `accept` is the dropzone's grammar (`"*"`,
  `"image/*"`, an exact mime, or several), spelled structurally since core
  cannot name the web type.
- `mediaFieldDefOf(field)` — from the slot's erased def back to the
  `MediaFieldDef` (`accept` / `max` / `maxBytes`); throws for a def another
  factory built.
- `mediaAttachmentIds(fields, values)` — every attachment id the media fields
  of a `FieldsRecord` hold, in order. Generic: it dispatches on
  `field.type.id` and names no consumer. An owner calls it on save to set its
  owner links (`Attachments.defineLink`), which is what keeps the files from
  the orphan sweep. Top-level fields only; `values` must be resolved — a
  missing or malformed media value throws.

## Web

`web/` registers the identity and exports `MediaThumb` — one ref as a small
square (an image, a video's first frame through a muted
`<video preload="metadata">`, else a file glyph), loaded over the subtree's
transport (`useAssetSrc` on `getAttachmentFile`), reporting the file's
metadata once the browser has read it. Shared by both capability children.
`ViewableMediaThumb` is the same square, opening its file in the enclosing
`<ImageGallery>`'s viewer (`primitives/overlay/image-viewer`) on click — an
image to zoom, a video to play, ← / → through the gallery's other files; any
other file stays a plain thumbnail. It throws outside a gallery.

## Children

- `config` — the `Fields.Renderer` (a `block`: reorderable thumbnails in one
  gallery — click to open, drag to reorder — remove,
  then the `UploadDropzone` while there is room) and the `Fields.Sample`.
  Renders inside any `FieldsForm`. Each upload is **held** (holder
  `fields.media:<per mount>`, 24 h) so the orphan sweep cannot reap a file the
  form shows before its owner saves and links it; a failed hold is shown, not
  swallowed. A ref missing its pixel size / length gets it from its
  thumbnail's load, once.
- `table` — the `DataViewSlots.Cell` (first thumbnail + `+N`) and
  `mediaFieldDef({ id, label, media })`, the typed spelling of a DataView
  media field (`data` = the refs; a wrong payload throws in the cell).
- `storage` — a `jsonb` column decoded by the field's own schema (the
  `decode` arm, like `tags`).
