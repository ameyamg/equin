# formatted-text

The **formatted-text** field type: plain text with a small, safe inline
markup — bold, key caps, links, line breaks; nothing else. The value is
stored as its **source** (a string); every surface parses it the same way
(`parseFormattedText`, core) and draws it with `FormattedTextView` (web).
First user: a tip's text (`apps/website/pages/tips`).

## The syntax

| write | reads as |
|---|---|
| `**Drop & Close**` | **Drop & Close** — bold (a button's or menu's name) |
| `<kbd>⌘</kbd>+Click` | a key cap, then `+Click` |
| `[the tips](/about/tips)` | a link: `https://…`, `http://…`, `mailto:…`, or a path on the same site (`/…`) |
| a newline | a line break; a blank line spaces paragraphs |
| `\*`, `\[`, `\<` … | the character itself (escapable: `\ * [ ] ( ) < >`) |

- Bold may hold key caps and links; a link's text may hold bold and key
  caps. Spans nest properly or not at all.
- A link's target ends at its first `)` and holds no space, `<`, `>`, `"`
  or `\` (a browser reads `\` as `/`, so `/\evil.com` would leave the
  site): write a `)` in a URL as `%29`.
- A key cap's content is literal text on one line (`<kbd>Ctrl</kbd>`,
  `<kbd>↓</kbd>`); one key per `<kbd>` — `<kbd>Ctrl</kbd>+<kbd>F</kbd>`.
- **Nothing is ever an error.** A marker that does not close (`2 ** 3`,
  `**open`), an empty one, or a link to any other scheme (`javascript:`,
  `data:`, `//host`) stays literal text. So plain text written before this
  field existed reads the same, unless it holds the markers above.
- Parsing is linear in practice: an opener that runs to the end unclosed
  makes every later opener of its kind fail at once (none of them has a
  closer left), so crafted input (`"**[ ".repeat(n)`) cannot freeze a page.
- No headings, lists, italics, code, images or raw HTML: a formatted text is
  one run of prose.

**Why this spelling.** Agents write it and reviewers read it as a diff, so
it is plain text in the conventions both already know: Markdown's `**bold**`
and `[text](url)`, and the `<kbd>` GitHub Markdown uses for keys. Markdown's
backticks are NOT a key cap: inline code and a key are different things, and
the field has no code.

## API

- `core` — `formattedTextFieldType` / `formattedTextIdentity` (`extends`
  multiline-text, so a table cell or filter without its own shows the source
  as long text); `parseFormattedText(source) → FormattedText` (total: every
  string parses), the node union `FormattedInline` (`text` — may hold `\n` —
  `strong`, `key`, `link`), `formattedPlainText` (formatting dropped, a key
  as its key, a link as its text), `plainFormattedText` (a plain string as
  one run, no markup read), `isSafeFormattedHref`.
- `web` — `<FormattedTextView source as? className?/>`: the source drawn in a
  `<span>` (or `p` / `div`), `whitespace-pre-line`; bold as `<strong>`, a key
  as a `<kbd>` key cap (`formatted-text-view.css`), a web or mail link in a
  new tab, a site path in place.
- [`config`](plugins/config/CLAUDE.md) — `formattedTextField({ label, rows,
  default })` and its config renderer: the source in a textarea, the syntax
  in one line under it, then the draft drawn by `FormattedTextView`.

Converting for another format is the consumer's: walk the parsed nodes (the
Discord target writes bold as `**…**`, a key as inline code, a link as a
masked link — `apps/deploy/site-feeds/discord`).

Tests: `core/internal/parse.test.ts`.
