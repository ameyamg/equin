# box

Site feeds on the deployed box — and on this instance, which runs the box half
too and is a copy of the site of its own: the published copy of each feed's
entries and everything that reads or writes it. It knows no SSH and no editor
— the computer holding the items (the source of truth) writes a deployed box
through the host-only routes [`site-feeds`](../../CLAUDE.md) declares, and
this instance's own copy in-process (`upsertSiteFeedEntry` /
`deleteSiteFeedEntry` / `missingSiteFeedMedia` + `presentSiteFeedMedia`, the
same code the routes run, exported from `server/`).

**A site renders a feed by importing the `web` barrel** (`useSiteFeed`), never
only `core`: a composition's closure follows same-runtime imports, so the
import is what ships this plugin's server and machine halves with the site
(the `site-messages/intake` rule). `attachments` comes with it (load-bearing,
and imported by the server half).

## Registry — `SiteFeeds.Feed({ feed })`

Both runtimes, one name. The server kind (`server`) is what every write is
validated against and what the public read admits (`siteFeedOf(id)`); the web
slot (`web`, data, never drawn) is what the editor lists, read with
`useSiteFeedDeclarations()` → `{ feed, pluginId }[]` — the plugin id is the
contribution's own stamp, what `useDeploymentShips` asks a deployment about.
The server twin, `siteFeedDeclarationOf(id)` → `{ feed, pluginId } | null`, is
what the editor resolves a feed's destinations with.

## Tables

- `site_feed_entries (id pk, feed_id, values jsonb, published_at, updated_at)`
  — `values` validated on write against this release's declaration; `id` is
  the computer's item id (unique across feeds, never moved to another feed).
- `site_feed_entries_attachments` — `Attachments.defineLink` over it (pk
  `(owner_id, attachment_id)`, cascading): what keeps a published entry's
  media from the orphan sweep and what the media route checks. Set to exactly
  the values' `mediaAttachmentIds` on every upsert; gone with the entry.
- No mirror set: the computer is the source of truth, so nothing is copied back.

## Reads

- **`site-feeds.entries`** (`siteFeedEntries`, core) — `liveValue`, param
  `feedId`, `{ entries }` capped at `SITE_FEED_PUBLIC_LIMIT_MAX`; served
  `source: "db"`, the feed's newest `publicLimit` entries (`published_at desc`),
  each re-read through the declaration (a field added since takes its default,
  a removed one is dropped; one that no longer parses fails the read —
  `StoredEntryInvalidError`). Visitor-readable for a feed this release
  declares (`visitorTuple`), else refused `unknown-feed`. `preload: "boot"`,
  one tuple per declared feed under its declaring plugin, so the site's first
  frame — and the crawl snapshot's static render — has it.
- **`useSiteFeed(feed)`** (web) → `loading` | `error { error, refetch }` |
  `ready { entries }`, each entry's values parsed by the feed's own schema
  (typed `SiteFeedValues<F>`).
- **`GET /api/site-feeds/media/:entryId/:attachmentId`** (`siteFeedMediaFile`,
  visitor) — the file only while that entry links that attachment (404
  otherwise), byte ranges (`rangedBlobResponse`: video seeks),
  `cache-control: public, max-age=31536000, immutable`. In the browser:
  `useAssetSrc(siteFeedMediaAsset(entryId, attachmentId))`.

## Writes (host-only, behind `hostOnly` and Caddy's `/api/host-only/*` 404)

- `server/` — `entries/upsert` (`capBodySize(64 KB)`; `judgeUpsertValues`,
  exported as `judgeSiteFeedValues` so the editor's saves judge alike:
  zod issues, and a key the declaration lacks, are `invalid-values`; every
  referenced attachment must exist → `missing-attachments`), `entries/delete`,
  `media/missing`.
- `machine/` — `media/import`: reads `siteFeedsStagingDir/<stagedName>`
  (`data-dirs`, a `cache` dir), checks size then sha256, imports it with
  `importAttachmentFile` under the given id (idempotent: `exists`; another
  size: `conflict`), and removes the staged file whatever the verdict.
  `site-feeds.staging-sweep` (daily, `perWorktree`) deletes staged files older
  than a day — what an interrupted publish left.
