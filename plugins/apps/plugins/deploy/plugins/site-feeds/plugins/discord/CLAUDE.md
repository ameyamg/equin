# discord

Discord as a [`syndication`](../syndication/CLAUDE.md) target: an item becomes
one message in a channel, through the channel's webhook. The only code that
knows Discord. Design: decision 9 of
[`research/2026-11-25-global-site-feeds.md`](../../../../../../../../research/2026-11-25-global-site-feeds.md).

## Config

`discordTarget` (core): `webhookUrl` — a `secretField`, read by
`parseDiscordWebhookUrl` (`https://discord.com/api/webhooks/<id>/<token>`,
also `discordapp.com`, `ptb.` / `canary.`, `/v<n>`; anything else refused at
save once the target is on) — and `uploadLimitMb` (default 10; 50 at boost
level 2, 100 at level 3). An MB is 1 000 000 bytes, a little under Discord's
own, so a plan that fits here fits there.

## A message (machine)

- `content` (`discordContent`): the title in **bold** (its `*` escaped), then
  each paragraph, blank lines between; ≤ 2000 characters, else refused before
  anything is sent. `allowed_mentions: { parse: [] }`: a tip never pings.
- ≤ 10 files, multipart `payload_json` + `files[i]` (`discordForm`), each
  listed in `attachments` by index; `POST …/webhooks/<id>/<token>?wait=true`
  answers the message, whose id is the post's `remoteId`.
- **The files must fit ONE request** (`planUploads`, pure): everything under
  the limit → sent as is. An image is never re-encoded: over the limit, or
  leaving no room, the post is refused with each file's size and the limit.
  Otherwise the videos share what the rest leaves — a small one that fits its
  equal share is sent as is, the others re-encoded to an equal share of what
  is left (`transcodeToBudget`, into the run's work dir). A video too long for
  a watchable bitrate at its share (`too-long`), or still over it
  (`over-budget`), refuses the post. Never a link instead of the file.
- Edit: `PATCH …/messages/<remoteId>` with the new text and files (the
  `attachments` list replaces the old ones); a message deleted in Discord
  (404, code 10008) is posted anew, and its new id kept. Remove: `DELETE`;
  already deleted is done. A deleted webhook (10015) is refused: paste a new
  URL.
- `parseDiscordResponse`: 429 (with `retry_after`) and 5xx are retryable,
  every other refusal is final, with Discord's own message. The job's retry
  backoff (seconds, then tens of seconds) is longer than a webhook's usual
  `retry_after`; it is reported, not slept on.

## Tests

- `machine/internal/discord-api.test.ts` — webhook URL spellings, URLs, content,
  payload and multipart, every answer the parser reads.
- `machine/internal/upload-plan.test.ts` — the budget across files: kept,
  re-encoded to equal shares, refused (an image over, no room left), never
  over the budget in total.
- Not covered without a real webhook: Discord accepting the multipart as
  built, an edit replacing attachments, the re-encoded video playing inline.
