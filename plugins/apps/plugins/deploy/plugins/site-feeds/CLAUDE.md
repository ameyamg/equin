# site-feeds

Content a deployed site publishes itself — equin.ai's tips of the day, a
site's news — written on this computer, published to every copy of the site
serving the feed (this instance's own, in-process, and — from main only —
each deployment shipping the feed's declaring plugin), read by its visitors
live, and posted to other services once per item. Design:
[`research/2026-11-25-global-site-feeds.md`](../../../../../../research/2026-11-25-global-site-feeds.md),
v2 (items owned by the feed, destinations, the Feeds page):
[`research/2026-11-26-global-site-feeds-v2.md`](../../../../../../research/2026-11-26-global-site-feeds-v2.md).

**Nothing here names a feed or a field.** A feed is declared by the site
plugin that renders it (`apps/website/pages/tips` is the only code that knows what a
tip is); the Deploy app reads the declarations.

## `defineSiteFeed` (core)

```ts
export const tipsFeed = defineSiteFeed({
  id: "tips",                      // SITE_FEED_ID_PATTERN
  label: "Tips of the day",
  fields: { title: textField(…), body: multilineTextField(…), media: mediaField(…) },
  syndicate: { text: ["title", "body"], media: "media" }, // keys of `fields`
  publicLimit: 60,                 // 1..SITE_FEED_PUBLIC_LIMIT_MAX (100)
  pagePath: "/tips",               // optional: the feed's page on a deployed site, what posts elsewhere link to
  localPagePath: "/about/tips",    // optional: the same page in this app — this instance's own copy of the site
});
// → SiteFeedDecl<F>: { id, label, fields, syndicate?, publicLimit, valuesSchema }
```

- `fields` is a plain `FieldsRecord`; `valuesSchema` is `fieldsToZodObject(fields)`
  (a missing key heals to its default). Values type: `SiteFeedValues<F>`.
- `syndicate.text` / `syndicate.media` are typed against the field keys, and
  `media` must name a `mediaField` (`MediaFieldKeys<F>`): a wrong key is a tsc
  error, and throws at declaration for an untyped caller
  (`SiteFeedDeclarationError`, with the id's spelling, the field count ≤ 32
  and `publicLimit`). No `syndicate` → the feed is never posted elsewhere.
- The site registers the SAME declaration in both runtimes, through
  [`box`](plugins/box/CLAUDE.md)'s `SiteFeeds.Feed({ feed })` — the server
  registry validates writes, the web slot feeds the editor. The declaring
  plugin is the contribution's own stamp, never restated.

## The host-only route contracts (core)

What the computer calls on the box over SSH (the `analytics/host-only` rules:
under `/api/host-only/`, one `?q=` base64url question for a GET). Every
refusal is an arm of a 200 answer, never a bare status — the table mirror's
`unknown-set` precedent — so the caller reads why from the typed body.

| endpoint | route | answer |
|---|---|---|
| `siteFeedUpsertEndpoint` | `POST …/site-feeds/entries/upsert`, JSON `{ feedId, id, values, publishedAt }` ≤ 64 KB | `upserted { id, updatedAt }` · `unknown-feed` · `invalid-values { issues }` (THIS box's declaration — skew: deploy the site) · `missing-attachments { attachmentIds }` (import them first) |
| `siteFeedDeleteEndpoint` | `POST …/site-feeds/entries/delete`, `{ feedId, id }` | `deleted` · `absent` · `unknown-feed` |
| `siteFeedMissingMediaEndpoint` | `GET …/site-feeds/media/missing?q={ attachmentIds }` (≤ 100) | `{ missing }` — transfer only these |
| `siteFeedImportMediaEndpoint` | `POST …/site-feeds/media/import?q={ attachmentId, filename, mime, size, sha256, stagedName }` | `imported` · `exists` · `staged-missing` · `size-mismatch` · `sha256-mismatch` · `conflict` |

An entry id (`siteFeedEntryIdKind`, `sfe-…`) is the item's id on the
computer (minted there), so publishing again is an upsert. An attachment id is the
computer's (a lowercase UUID): one id is one file everywhere, so a re-publish
transfers nothing it already did. The media flow: ask `missing`, `scp` each
missing file into the box's staging dir (`siteFeedsStagingDir`, box's
`data-dirs`), `import` it, then `upsert`.

## Children

- [`box`](plugins/box/CLAUDE.md) — ships IN the site: the registry, the
  published entries, the public read and media route, the routes above.
- [`editor`](plugins/editor/CLAUDE.md) — local only: the items (owned by
  their feed — the source of truth), the Deploy app's Feeds page, the
  destinations (this instance; deployments shipping the feed, from main
  only), the publish job per item and destination, and the once-per-item
  `siteFeeds.itemPublished` / `itemUnpublished` events.
- [`syndication`](plugins/syndication/CLAUDE.md) — local only: posting
  published items to other services (the `SyndicationTargets.Target` open
  set, per-feed target settings, a job per item and target, Send test post).
- [`discord`](plugins/discord/CLAUDE.md) — local only: the Discord webhook
  target.
