# mail/reader

Reading a thread (design §3–4 of
[`research/2026-11-26-apps-mail-on-demand-cache-provider.md`](../../../../../../research/2026-11-26-apps-mail-on-demand-cache-provider.md),
step 5). The threads plugin opens it beside the list (`/mail/thread/<id>`,
`threads/web/panes.tsx`); this plugin draws the thread and serves what it loads.

## `mail.thread` (`core`)

One thread by id, served from the Mail cache (`cache/server`'s
`mailCache.thread`): its stored body while that body holds exactly the
thread's messages, else fetched from the provider (the read stays loading).
NOT cache-only: any thread id is read, listed or not. Re-pushed when the cache
learns the thread moved (`onMailThreadsChanged`: read elsewhere, relabelled, a
reply). Refused `gone`, `not-connected` (the provider's connect surface) or
`offline-not-cached`. Opening marks nothing read (step 6's write).

## Safe HTML (`server/internal/render.ts`, `web/internal/mail-frame.ts`)

- **The frame is the boundary.** Each HTML body is its own
  `InlineFrame fit` (`primitives/embed/frame`): an opaque origin, as tall as
  the message, its only script the frame's nonce'd height reporter — the
  body's own scripts, handlers and `javascript:` never run. The page frames
  the body under the **mail policy**: images only from this server's
  `/api/mail/` routes or `data:`; inline styles and `data:` fonts; no
  stylesheet, font, media, frame, object, form, worker, connection or base.
- **The server's rewrite keeps mail working inside that policy**, not safe:
  remote `<img>`, `background` and inline-style `url()` through the image
  proxy (decided: load by default — the sender never sees the reader's
  address, tracking pixels still fire), `cid:` images through the
  inline-part route, `http(s)`/`mailto` links to a new tab
  (`allow-popups-to-escape-sandbox`). It cuts what the policy cannot: a
  `<meta http-equiv="refresh">`, `<link>` prefetches, `<base>`. An image in a
  `<style>` block is not rewritten: the policy blocks it.
- **The frame's requests are anonymous** (opaque origin), so the image and
  inline-part routes are public — each URL carries this server's HMAC of what
  it names (`server/internal/sign.ts`, a key per process: a restart re-renders
  every open body). Only a URL the server wrote into a body it rendered is
  served. The image proxy is SSRF-guarded (`infra/safe-fetch`), image types
  only, 10 MB.
- **Every answer is untrusted bytes on the app's origin**: `nosniff`, a
  `sandbox` policy, and anything a browser would render as a page (HTML, SVG,
  …) served as a download.

## Attachments

`GET /api/mail/attachment/:threadId/:messageId/:partId` (owner): opened in a
tab (images, PDF, text, audio, video) or downloaded (`?download=1`, and every
other type). Parts are kept in `infra/attachments` under a name-derived UUID
(v5 of thread, message and part): the next open reads them from there. Unlinked,
the attachments sweep reclaims them after an hour; the open after that fetches
them again.

## The pane (`web/components/thread-reader.tsx`)

The prototype's reading pane: a bar (Close), the subject and message count,
the messages oldest first — the last and the unread ones open, the others
folded to one line (a click opens one) — an HTML body framed on a light page
of its own, a text body as text, each message's files. Not yet: the label
chips, the actions (step 6) and the reply bar (step 7).

## Measuring

`e2e/open-speed.ts` (manual: a connected account): time from a row's click to
the painted body, prefetched vs cold.
