# local

The **local mail provider** (id `local`, "This device"): a `MailProvider`
whose mailbox lives in this host's own database. No network, no computer, so
its server barrel is portable — the website's live demo serves Demo's mailbox
from the browser's PGlite. Design:
[`research/2026-11-27-global-mail-in-browser-demo.md`](../../../../../../../../research/2026-11-27-global-mail-in-browser-demo.md) §1.

- **Not on main.** `all-exclusions` negates it (`!apps.mail.providers.local`):
  the cache serves exactly one provider, so a composition ships it instead of
  Gmail (`agent-manager-demo` names it and negates Gmail). Main's page (and the
  website's) still holds its web half **on demand** (the web registry's
  `webScopedEntries`), since the live demo's scope names it: loaded into the
  demo on Enter and visible only there, so main's page root never sees a
  second `MailProviderUi.Connect` and main's backend never a second provider.
- **Tables** (`server/internal/tables.ts`): `mail_local_accounts` (one row,
  id `local`), `mail_local_mailboxes` (labels only: role mailboxes are the
  provider's constants), `mail_local_messages` (participants and
  `mailboxes` as jsonb, the filter language's `stringArray`),
  `mail_local_attachments` (bytes in `bytea`), `mail_local_changes` (the
  change log). Every time is a `timestamptz`, so a demo snapshot's time shift
  moves them all.
- **Queries.** The provider query is the canonical filter JSON
  (`provider/core`'s `compileCanonicalMailQuery`, shared with the test fake),
  compiled to SQL by `network/live/filter`'s `filterSql` over per-column
  targets (`QUERY_TARGETS`: `from` / `to` written as headers write them,
  `query` the subject, sender, recipients and text — the same text the fake
  matches in memory, so the contract test holds the two to the same answer).
  `listMessages` pages by `(date, id)` with `limit`.
- **Writes** are idempotent target-state writes, each ONE atomic statement
  (`writeAtomically`) that also appends to the change log; a thread's version
  is the latest `seq` naming it, the change cursor the log's `seq`. Every
  write runs in a transaction that first takes one advisory lock
  (`pg_advisory_xact_lock(hashtext('mail_local_changes'))`), so commit order
  is `seq` order (a reader past `seq` N never misses a row committed later
  with a smaller one) and what a write checks — a label exists, a name is
  free, which messages a deleted label strips — holds until it commits.
  Reads that combine facts and a version (`getThreads`, `getThreadContent`)
  read one repeatable-read snapshot, so "same version ⇒ current" holds.
  `send` parses the bytes back (`packages/mime`'s `parseMimeMessage`) and
  stores them whole (Bcc, Reply-To, a body's unknown charset, which parts
  are inline) in Sent, threaded by In-Reply-To / References — never
  delivered anywhere; a message to the account's own address also lands in
  its Inbox. A replayed send answers the message it stored.
- **Deleting a label** moves its sub-labels up to its parent; one whose name
  is already taken there is refused (`MailRefusedError`, nothing written), as
  a rename or move onto a taken name is.
- **The change log is never pruned** (no retention): a local mailbox is a
  demo's or a test's, small and short-lived. A long-lived one would need a
  floor below which `changesSince` answers `reset`.
- **Push** is in-process and always `live`: every write this process commits
  signals it, so the cache never relies on its fallback tick.
- **`localMail.deliver`** is the inbound write — mail arriving, which no user
  endpoint makes — and **`localMail.setAccount`** sets up the account; both
  are what `apps/mail/fixtures`' `writeMailFixture` calls.
- **Web:** its `MailProviderUi.Connect` says the server's sentence ("No local
  mailbox on this device.") — shown only when nothing was set up.
- **Test:** `server/internal/provider.test.ts` runs on a throwaway database
  (the real migrations) and holds every `MAIL_QUERY_OPS` pair to the fake's
  in-memory answer, plus writes, changes, drafts and send threading.
