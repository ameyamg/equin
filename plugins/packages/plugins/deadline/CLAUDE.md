# deadline

`withDeadline(work, budgetMs, onTimeout)` awaits `work` for at most `budgetMs`.
On expiry it rejects with the caller's `onTimeout()` error; when `work` rejects
first, its own error wins. The timer is one-shot and always cleared, so a fast
success leaves nothing pending.

It **bounds the wait, never the work**: nothing is cancelled. The caller keeps
its handle on `work` and decides what a still-running promise means (keep a
memo, report it, leave it running). Use it for an await with no timeout option
of its own — a module import, a run a bug may never settle.

## `deadline/no-wall-clock-deadline` (lint)

A `setTimeout` whose callback gives up on work — calls `reject`, `.abort()`,
`.kill()` or `process.exit()` — is a deadline, and `setTimeout` counts machine
sleep: on wake every timer whose time passed during the nap fires at once, so
work that ran 0.3 s awake is declared failed (report-1795305324-8wpwx2: a launch
failed `AgentNotRunningError` 104 ms before its agent said it had started).
The rule reports it everywhere except browser code (`web/`, `e2e/`,
`exhibits/`), tests and generated files; use `armAwakeDeadline` / `withDeadline`.
A deadline that really is on wall time (a remote peer's lease, an external
token) is declared in the plugin's `exempt/index.ts`, with its reason.

`AbortSignal.timeout(ms)` is the same deadline with the timer hidden inside
the runtime, and the rule reports it too: use `awakeTimeoutSignal(ms)` (here),
which aborts with the same `TimeoutError` `DOMException` after `ms` of awake
time. Found by the 2026-11-24 audit: 41 calls outside browser code, 30 of them
to this machine's own gateway, backends or sockets — a build's adopt request
made before a nap was aborted on wake ("no answer to the adopt request (The
operation timed out.)", build-1795343567-5hlm5g), so the build restarted the
backend it could have adopted. All 41 now count awake time; a remote peer that
does not answer in N awake seconds is as good a verdict as N wall ones.

It recognises the give-up by the callback's own calls, so a debounce, a backoff
or a `setTimeout(resolve, ms)` sleep is not reported — and a watchdog that only
sets a flag or resolves `"timeout"` is not either; those still belong on
`armAwakeDeadline`.

## `deadline/no-unstated-wall-age` (lint) and `wallNow(reason)`

The other half of the class: an AGE or a deadline check computed by
arithmetic on the wall clock. The rule reports a bare `Date.now()` (or
`new Date().getTime()`) that is an operand of `-`, `<`, `<=`, `>` or `>=` —
directly, or through the `const` or parameter default it initialises
(`const now = Date.now(); … now - row.at`). Same scope as its sibling: not
browser code (`web/`, `e2e/`, `exhibits/`), tests, research or generated
files. A stored or logged instant, an expiry computed with `+` (judged where
it is compared) and `performance.now()` arithmetic are not reported.

Two ways out, and the rule makes you pick one:

- **Awake time**, for anything that judges work this machine runs: a
  `performance.now()` difference (`awakeClock`) when both ends are read in one
  process; `clockStampNow()` + `awakeBetween` for an instant stored and judged
  later (`packages/sleep-clock` § Judging an age); `armAwakeDeadline` for a timer.
- **`wallNow(reason)`** (here, web-safe), when the wall clock is right: it is
  `Date.now()` with a `WallClockReason` — `retention`, `expiry`, `external`,
  `schedule`, `fail-open-lease`, `human-time`, `lookback`, `sleep-detection` (each documented on
  the union). The choice is a typed argument, not a comment: tsc rejects a
  missing or misspelled one, and `rg 'wallNow\("'` lists every deliberate
  wall-clock judgement in the repo.

What it cannot see: a wall instant passed out as an argument or a field and
subtracted elsewhere (`age(Date.now(), at)`), and ages in browser code. The
timer half is still the give-up heuristic above; a timer that only sets a flag
or resolves `"timeout"` is not reported.

Used by `infra/safe-fetch/browser-fetch` (the Playwright import) and
`conversations/runtime-sdk` (the event consumer's catch-up watchdog).
