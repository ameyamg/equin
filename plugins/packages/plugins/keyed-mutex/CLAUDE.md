# keyed-mutex

Per-key FIFO mutex: `createKeyedMutex(name)` returns `{ run(key, fn), size }`.
`run` starts `fn` once every earlier `run` for the same key has settled, in
arrival order; different keys never wait on each other. Each call runs its own
`fn` exactly once and gets its own result or rejection — a failure never stalls
the calls queued behind it. A key's entry is deleted by the run that is still
its queue's tail when it settles, so an idle key holds nothing.
`run(key, fn, { signal })` bounds the wait: a call still queued when the signal
aborts rejects with its reason and never runs, while the calls behind it keep
waiting for the runs ahead (`infra/paths/data-files`' `withLock` arms its
deadline before the queue this way).

**A queued caller holds no use-scoped gate slot while it waits**
(`packages/semaphore`): inside the live read gate a slot is held only around a
DB statement, file call or child process, so waiters can never fill the gate in
front of the holder's next use — the 2026-11-17 `cost-at` wedge (waiters held
the key's whole read share while the holder waited for a slot to take back).

**A queued caller's wait is named** `mutex:<name>`: shown from the moment it
queues behind a run of its key, charged as its turn comes (a `queue` wait the
runtime profiler installs through `installKeyedMutexWaitMeter`, as `inflight`
does its joins). So a request that sat on a lock names it in its trace instead
of booking the holder's run as its own time — 2026-11-22, a rewind queued 25 s
behind a Stop on `conversations.agent-lifecycle` read as 26 s of "own" time.
An uncontended run meters nothing.

Neighbours, and why they do not fit a mutation that must not interleave:

- `packages/coalesce` FOLDS the triggers that land mid-run into one trailing
  run — a second send would be merged into the first.
- `packages/inflight` SHARES one execution among concurrent callers — a second
  send would be dropped.
- `packages/semaphore` bounds concurrency across all callers, with no per-key
  queue.

In-process only. It orders the callers of one process; two processes need a
lock both can see (a pg advisory lock, `packages/flock`).

Used by `conversations` to serialize everything typed into one agent's terminal
(send, answer, interrupt, Stop): two sends to one pane interleaved their
keystrokes into one concatenated turn.
