# process-alive

Is the process that wrote this still running? `isProcessAlive(pid)` asks the
kernel (`kill(pid, 0)`): ESRCH is dead, EPERM (another account's process) is
alive, anything else throws, and a non-pid (0, negative) is refused —
`kill(0, 0)` would probe the caller's own process group.
`isProcessGroupAlive(pgid)` is the same reading for `kill(-pgid, 0)`: any
member of the group remains (supervised-job judges a run by its group).

**The one copy.** It was hand-rolled 22 times and the copies drifted (some
read every error but EPERM as dead, one every error but ESRCH as alive);
`process-alive/no-signal-zero-probe` now rejects `process.kill(x, 0)` outside
this plugin (tests excepted).

**Temp sweeps judge the writer, not the file's age.** A writer that names its
temp file with its own pid (`<target>.tmp.<pid>…`) lets a sweeper decide
exactly: `isOrphanedTemp(name, pattern)` — the pid the pattern's first group
captures is gone, or the name carries none. An mtime grace ("older than 10
minutes is orphaned") counts machine sleep: a Mac that sleeps mid-build lets a
sweeper woken first delete a live writer's temp, and the writer's rename then
fails. A reused pid only keeps an orphan longer (until that process exits),
never deletes a live writer's file.

`isOrphanedTemp` is used by the web-artifacts served-dist memo sweep, the check
cache's temp and flight-publish sweeps, and corpus-index's checkpoint sweep.
