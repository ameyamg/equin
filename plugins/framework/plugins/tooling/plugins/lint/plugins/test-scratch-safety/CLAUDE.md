# test-scratch-safety

`no-source-tree-write`: a test file, or a `testing/` fixture, never creates,
writes, moves or removes a path whose **base** is its checkout. The base is
where the path is rooted: the first argument of `join` / `resolve` / `dirname` /
`mkdtemp`, the head of a template or `+`, either branch of `?:` / `??`, and
every value a binding is given (a `let` set in `beforeAll` too). Checkout
bases: `import.meta.dir` / `dirname` / `path` / `url` / `filename`,
`__dirname`, `process.cwd()`, an imported repo-root constant (`REPO_ROOT`, …,
aliased or through a namespace) and a zero-argument root getter
(`getMainRepoRoot()`, `getWorktreeRoot()`, …). Only the destination is judged:
copying a repo file out or symlinking into the tree from a temp dir is fine.
Make scratch under `os.tmpdir()`: `./equin test` points `TMPDIR` at the run's own
root and removes it ([`cli/test`](../../../../../cli/plugins/test/CLAUDE.md)).

Why: main runs its tests right after it deploys, **inside the slot it serves
from**. On 2026-11-24 a config test's probe dir beside the test
(`.config-test-*`) was met by main's faceted plugin-tree walk, whose disk-read
guard failed the build (report-1795554708-scgii6). The test removed the dir in
`afterAll`, so a before/after comparison of the tree would never have seen it —
the write itself is what has to be refused.

What it does not see: a bare relative path (`writeFileSync("x")`, resolved
against the cwd), a write inside a helper function, and a write reached
indirectly — a CLI a test spawns writing into the checkout because of the
environment it was handed (the installer dry-run's re-pointed
`node_modules/.cache` link, fixed in b94f07bf76). When
the rule was added it fired on one file of 3,367 test and `testing/` files (the config test, fixed with it).

A file that must write into its checkout is exempted by its own plugin
(`exempt/index.ts`), with the reason.
