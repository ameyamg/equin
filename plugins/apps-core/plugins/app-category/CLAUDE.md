# app-category

Each installed app's category: one nested tag tree the USER owns, and the one
tag each app is filed under. Design:
`research/2026-11-24-global-app-categories-and-isle-grouping.md`.

## Mental model

- **The tree** is a `tag-tree` declaration (`app_category_tags`, id kind
  `apcat-…`, tree id `app-categories`): renamed, nested, recoloured, reordered
  and deleted through the shared tag picker, like Places' and Prototypes' trees.
- **An app declares only a default** — `defineApp({ category: ["Leisure",
  "Music"] })` (`primitives/pane/core`, `AppCategoryPath`). It is where a newly
  installed app LANDS, never where it is: the `app-category.file-new-apps`
  warm-up (server, every boot) files each declared app with no
  `app_categories` row under its path, creating the missing tags
  (`ensureTagPath`, the engine's `/paths` write). From then on the row is the
  user's: a later change to the default in code moves nothing.
- **The assignment** is its own table (`app_categories`: app id → tag id or
  null), because apps are code, not rows. No row = not filed yet; `null` = left
  uncategorised (or its whole branch deleted). Deleting a tag lifts its apps to
  its parent (`singleTagCarrier`).

## Reading it

- `useAppCategories()` (web) — app id → `{ tagId, path }` (path root first) or
  `null`, live; an app absent from the map is uncategorised. Isle places its
  buildings by it (a district per leaf, neighbours per root).
- The **Category field** of every list of apps: a client field of
  `installedApp` (`appCategoryFields`), type `tag`, its options the live tree —
  so the Home gallery groups by it as nested sections, filters and sorts by it.
- **Change category** — an item action contributed to
  `AppLauncherSlots.AppActions` (drawn by the Home gallery, not the launcher's
  quick grid): the tag picker on the app.
- `useSetAppCategory()` / `PUT /api/apps/:appId/category { tagId | null }` —
  the one write (404 for an app the backend does not declare).

## Plugin reference

- Description: App categories, web half: each app's category as a `tag` field of every list of apps (group, sort and filter by it — grouping nests along the tree), a Change category action on every app of an app gallery (AppLauncherSlots.AppActions) (the shared tag picker over the app category tree), the app category id kind (`apcat-…`), and useAppCategories / useSetAppCategory for surfaces placing or filing apps by category.
