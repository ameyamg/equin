# auto-merge

Config updates merged automatically, for the user. When an update moves a
config's defaults under a user override, the registry (`config_v2/server`)
merges the override onto the new defaults itself whenever the merge decides
everything and passes the live schema, and leaves a record beside the
document (`<name>.merge.jsonc`). This plugin is everything about those
records except writing them. config_v2 never names it.

Design: [`research/2026-11-24-global-config-auto-merge.md`](../../../../research/2026-11-24-global-config-auto-merge.md)
(phases 2 and 3 of 6: record, auto-apply, Undo, the notification; the
developer review).

- **Live values** (`core/`): `config-v2.auto-merges` (every document with a
  record, as a summary: status, notes, removed fields) and
  `config-v2.auto-merge` (`{ path, scopeId? }`: the full record and where it
  stands — `current`, `superseded` by a later update, `edited` since, `undone`
  — and `editedFields`, the top-level fields the user changed since).
  Both read the store on load (the list memoized on each document's file
  stamps) and move with the registry's document fan-out
  (`onDocumentChange`), which every record write ends in.
- **Endpoints**: `POST /api/config-v2/auto-merge/undo` (targets → the
  registry's `undoAutoMergeByPath`, which leaves the record as an `undone`
  tombstone so the next boot does not merge the same update again; a target
  it refuses — `AutoMergeUndoRefused` only — is answered in `refused`, the
  rest undo), `/ack` (`stampAutoMergeByPath(…, "acknowledgedAt")`, only
  for the record it names — Dismiss / Mark reviewed) and `/resolve-field`
  (`resolveAutoMergeFieldByPath`: Keep records the choice; Use mine / Use new
  default rewrite one top-level field through the schema and mirror it into
  the record's `result`, so the merge stays current and Undo still restores
  the pre-merge state; refused — 400, `AutoMergeResolveRefused` — for a field
  edited since, a record replaced, undone or superseded, a removed field's
  Use mine, or a result the schema refuses).
- **Notification** (`server/`, the `config-auto-merge.notify` warm-up): one
  user notification per batch (category `updates`) for every current record
  no notification announced yet, each record then stamped `notifiedAt`; the
  row's dedupe key is the batch's record ids. Its action `config-auto-merge`
  is Undo for every announced merge still undoable, and draws nothing once
  none is (undone, superseded, edited).
- **Banner** (`web/`, `ConfigDetailSlots.Banner`): above the merged config in
  Settings → Config, by audience (`useAudience`):
  - a user: "Updated with the new defaults; your changes kept · N notes",
    each field the update removed, Undo (off once edited since), Dismiss;
  - a developer (marked): the review — when it merged and where it stands,
    Undo merge and Mark reviewed, and a DataView
    (`config_v2.auto-merge.review`) of every top-level field a side changed
    (`mergeReviewFields`, config_v2 core): old default, yours, new default,
    result, the outcome (its title says why), the review choice so far, and
    per-field Keep / Use mine / Use new default (`ReviewItemActions`, off with
    the reason when the choice would change nothing or the field was edited
    since). Shown after Mark reviewed too (a developer may revisit it).
- **Nav** (`ConfigNavSlots`): the `autoMerged` field (configs whose merge is
  in force — current or edited) that the authored `auto-merged` nav view
  filters on, and, for a developer, a notice counting merges in force nobody
  reviewed yet, whose Review switches the nav to that view.

Retired fields (phase 4): the banner names each field the update removed
(with the descriptor's reason) and each it renamed (your value moved with it);
the review lists a renamed field's old key as `renamed` (no Use mine) and its
new key as `carried`.

Not here yet (later phases): merging at a config
generation's derivation instead of at boot (5), the placement job (6).

## Plugin reference

- Description: Config updates merged automatically, in the app: above a merged config in Settings → Config, a line for users (updated with the new defaults, your changes kept, the fields the update removed, Undo, Dismiss) and for developers the review — every field the merge touched (old default, yours, new default, result, outcome and why) with Keep / Use mine / Use new default, Undo merge and Mark reviewed; the config nav's Auto-merged field (its authored view) and, for developers, a notice counting the merges not reviewed yet; and the Undo of the update notification announcing them (config-auto-merge). Serves the automatic-merge records the config registry writes when an update's new defaults merge cleanly under a user override: config-v2.auto-merges (every document with one) and config-v2.auto-merge (one document's record and where it stands — current, superseded, edited since), moved with the registry's document fan-out; and POST /api/config-v2/auto-merge/undo (put the normal conflict back) /ack (dismiss the note — Mark reviewed) and /resolve-field (the developer review's Keep / Use mine / Use new default on one field); and the config-auto-merge.notify warm-up, which writes ONE user notification (category updates, action config-auto-merge — Undo) for every merge record no notification announced yet, each then stamped notified.
