# side-note

A private note beside a composer: text the user keeps for themselves, never
sent. One subject (a conversation, a decision) has one note; its owner stores
it (a side-table, a live row whose `notes` is the text) and this plugin draws
it:

- `useSideNote({ subject, read })` — the note's state: `hasText` (the live
  draft when an editor holds one, else the saved text), `isVisible` (a note
  with text always shows, an empty one only while opened) and `toggleVisible`.
- `<SideNoteToggle subject read label />` — the note icon: opens and hides an
  empty note, a dot on its corner while the note has text (following the
  draft as it is typed, not the debounced save). The one place a failed read
  is reported.
- `<SideNoteArea subject read save keepField ariaLabel />` — the editor:
  debounced auto-save (`save("")` means delete), shown while visible;
  deleting the last of the text closes it, and Ctrl+Z brings it back.

`subject` must be unique across owners (`conversation:<id>`,
`decision:<id>`): the toggle and the area of one note sit in different
component trees and share their open / draft state by it.
