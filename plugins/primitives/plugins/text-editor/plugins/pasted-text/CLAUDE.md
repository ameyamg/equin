# pasted-text

A large paste in any `TextEditor` becomes a **pasted block** instead of a wall
of text in the draft. The prompt editor and the task-draft composer both get it,
since both are a `TextEditor`. Design: prototype `proto-1795704843-weeth6`.

- **Large** is 10+ lines or 1000+ characters (`isLargePaste`). Smaller pastes stay plain
  text, and a wrong guess is one click either way (Expand).
- **Measured as drawn**: `isLargePaste` takes the editor's token families (the
  slot's `extensions` prop) and counts each token as one character with none of
  its newlines, so a selection carrying `<ui-context>` chips (~900 characters of
  attributes each) pastes as chips, not as a block. The cut is
  `token-extension`'s `tokenizedSegments`, the same one the editor materializes.
- **The block** (`PastedTextBlock`) has a header `› <icon> Pasted log · N lines`
  (log / code / JSON / text, read off the body by `pastedTextKind`). It is folded to
  three faded lines and unfolds on click. While composing, the unfolded text is
  an editable textarea. On hover it shows Copy, plus Delete and Expand (back to plain
  text in place) while composing.
- **On the wire** it is `<pasted_content>\n…\n</pasted_content>`, no
  attributes, so the agent reads it as pasted material. It is deliberately not Claude
  Code's own `<pasted_content id="…">` grammar: `transcript-source`'s
  `unwrapPastedContent` strips that form on every transcript read, and a sent
  block would come back as different text (its pending turn never confirmed). A
  test in `transcript-source` pins that the id-less form is left alone.
- **Any body round-trips**: a `</pasted_content` inside the body gains one
  backslash on the wire (reversibly), so nothing pasted or typed can close the
  block early, nor match Claude Code's own closing tag (which the transcript
  would unwrap).
- **Read surfaces**: an `InlineTextWalkerSlot` walker (stage −2, first — before
  `go` and the active-data chips) draws the same block read-only in sent
  messages, the pending echo and task descriptions. The body is a component,
  so later walkers do not grow chips inside pasted text.

## How it sits in the editor

- The node (`core/node.ts`, decorated in `web/internal/pasted-text-node.tsx`)
  is an inline token whose text spans lines, registered with `spansLines: true`
  (see `token-extension`). The editor's line-by-line deserialization scans it
  over the whole text first, so a draft restore or reload gives the block back.
- The textarea keeps its own events: native listeners call Lexical's
  `stopLexicalPropagation`, so Enter does not send and a paste stays in it.
  The paste handler also declines `$isEventFromEmbeddedInput`.
- The paste handler (`PASTE_COMMAND`, NORMAL) declines files (the attachment
  upload's) and a Lexical clipboard (a copied block is rebuilt as a block anyway).
