# multi-select

Checkbox multi-select over one ordered list of ids.

- **`MultiSelectProvider({ keep, orderedIds })`** — the selection (a set and
  an anchor) over `orderedIds`; ids that leave `orderedIds` leave the
  selection; kept as view state under `keep` (`null`: not kept).
- **`useMultiSelect()`** — `selectedIds`, `selectedCount`, `isActive`,
  `selectAll`, `clearAll`, `setRange`. What a bulk action reads.
  **`useMultiSelectItem(id)`** — one item's `isSelected` / `toggle`
  (shift-click adds the range from the anchor).
- **`SelectionCheckbox`** — the native input (a dense table cell).
  **`SelectionBox`** — the drawn box (16px rounded square, outlined, filled
  primary with a check while checked; `role="checkbox"`), stopping its own
  click and pointer-down so the row under it neither activates nor drags. The
  host composes its reveal through `className`.
- **`useClearOnEscape(root)`** — Escape clears, as a surface shortcut of the
  list's region (`root`), registered only while something is selected; a
  plain key, so it yields to a focused text field.
- **`SelectionBar({ actions, placement })`**:
  - `"top"` (default) — a strip pinned under the scroller's top edge ("N
    selected", Select all, Clear, the actions). Render it before the rows.
  - `"bottom"` — a raised pill (`Surface level="overlay"`; its corners, block padding and lift the overlay token group's `selectionBar*`, its controls in the muted ink)
    centred at the bottom of the scroller's viewport ("N selected", the
    actions, a divider, a clear ✕): a zero-height `Sticky edge="bottom"`
    holding a `Pin to="bottom"`, so it takes no layout room; it slides and
    fades in, inert while nothing is selected. Render it AFTER the rows — a
    bottom sticky sticks within the box it ends.
