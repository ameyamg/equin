# box-presence

`generatesBox(el)`: is this element drawn as anything at all? The question a
popover asks of its anchor (`ui-kit`'s anchor-lost rule), the adaptive bar of
its row, the rail guard of the children it measures.

- `false` when the element left the document, is `display: contents`, or sits
  under `display: none` (itself or an ancestor, the `hidden` attribute
  included).
- `visibility: hidden` and a 0×0 box still generate a box.

In a browser the layout engine answers it (`getClientRects()` is empty exactly
when there is no box). jsdom has no layout engine and returns `[]` for every
element, so code reading the rects directly treats everything as hidden under
test — on 2026-11-19 (`1e701291e9`) every popover closed itself and three
suites went red. So the read has one home:

- A host with no layout engine declares itself once, at its entry:
  `declareNoLayoutEngine()` from `web/testing` (the repo's `test/setup.ts`
  does). It is then answered from the computed `display` up the ancestor
  chain — the same rule, minus geometry. Declaring twice, or after a box was
  read, throws.
- `box-presence/no-raw-box-presence` (lint) flags `getClientRects().length`
  everywhere else. Reading the rects themselves (`range.getClientRects()[0]`)
  is geometry, not presence, and stays allowed. Tests and e2e scripts (a real
  browser) are out of scope.
