# resize-loop-trace

## Held back, read at the error

The browser raises the loop error at the end of a rendering step in which a
notification could not be delivered. It says nothing about which. Right after
the step, though, every notification it could deliver has been delivered, so
the observations whose target is still out of date — its size differs from the
size it last reported, it was detached (the browser reports 0×0), or it never
reported — ARE the held-back ones. The tracer tracks each observation's last
reported size (its `box`: content-box or border-box) and reads them in the
error event. The next step's callbacks (`deferred`) are kept too, but they mix
the held-back notifications with whatever else resized that frame — on their
own they do not say which one looped.

## One report per episode

A loop that re-arms itself raises one error per frame: 489 in ~4 s from one tab
on 2026-11-27 (report-1795480778-ddn9y9), each its own report, request and
supervisor event. Errors less than `EPISODE_GAP_MS` (1 s) apart are one
episode, reported once when it goes quiet, with `occurrences` and `durationMs`
and the trace of its FIRST error. An episode is cut at `EPISODE_MAX_MS` (10 s),
so a loop that never stops still reports, every 10 s; leaving the page
(`pagehide`) reports the one running.

## Plugin reference

- Description: Names the observers behind a 'ResizeObserver loop completed with undelivered notifications' error, which the browser raises with no stack: installResizeLoopTrace() (imported first by main.tsx) wraps the page's ResizeObserver to remember the callbacks of the current pass, where each observer was created and the size each observation last reported. When the loop error fires it reads which observations are still out of date (resized or detached since they last reported, or never reported) — exactly the notifications the browser held back — and emits, on resizeLoopReportSink, ONE report per episode (loop errors less than a second apart, cut at 10 s): its first error's pass, held-back observations and next step, with how many errors it raised and for how long. claimsResizeLoopError(e) tells the window-error reporter the tracer reports this one.
