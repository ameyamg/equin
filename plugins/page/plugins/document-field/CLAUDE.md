# document-field

- `DocumentField`: one field over a document in a caller's `DocumentDialect`
  (pass a module-level dialect object: the field keys its plugins on it).
  Markdown and Rich faces, both editable; `readOnly` shows one (a mail's
  quoted original) in the same two looks.
- **A rich edit respells only the lines it touched**
  (`serializeDocumentKeeping`): every other line keeps the spelling the text
  has (`- `, `_x_`), as long as the whole still reads back as the forest;
  else (lines that don't map one to one, a one-line `<quote>x</quote>`) it
  is written canonically.
- **A change that can't be written as text** (the inline serializer throws)
  is shown under the field and not reported: the value stays the last one
  written, the text stays in the editor, undo goes on.
- **As an email** (`core/email.ts`): `forestToEmailHtml` (inline styles
  only, no font, colours from `EMAIL_TEXT_COLORS` — fixed values that read on
  white) and `forestToEmailText` (for a person: marks kept, tags dropped,
  quotes as `> `, nothing escaped). `plainTextForest` reads plain text as
  literal paragraphs.
- **An email's HTML as a document** (`core/email-html.ts`,
  `emailHtmlToForest`): the inverse, read from any sender's HTML (a
  reply's quote, a forward). Our own HTML reads back as the forest it was
  written from; others keep paragraphs (a `<div>` / `<p>` / `<br>` line
  each; a `<p>` with default margins set off by a blank line — unless its
  margin is set inline or by the message's own `<style>` sheet, as Outlook
  does; `<p>&nbsp;</p>` a blank line), headings,
  lists, quotes, code, rules, marks (tags and inline styles), web and mail
  links, and a colour snapped to the nearest text-colour token by hue
  (`nearestColorToken`; near black or very light stays default). Hidden
  content, images, tables (each cell a line) and fonts are drawn as text
  or left out.
