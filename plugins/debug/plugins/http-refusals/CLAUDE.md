# http-refusals

Counts every 4xx the serving backend answers — stage 0 of
[declared refusals](../../../../research/2026-11-26-infra-declared-refusals.md):
before endpoints declare which refusals are deliberate, measure how many there
are, per route and status.

- `http-router`'s `onRefused` hands each 4xx answer (matched route key, or
  `null` when no route matched) to `recordRefusal`, wired by server-core's
  `bin/serve.ts`. Only the serving backend records; central and browser hosts
  do not.
- One line per 4xx in the `http-refusals` channel:
  `~/.equin/worktrees/<wt>/logs/http-refusals.jsonl`, each line's `line` a
  JSON `{ route, method, path, status, message, bodyError? }` (`message`: the
  body's first 300 characters, read from a clone that is then cancelled;
  `bodyError` when the body could not be read). Bounded by the channel sink's
  rotation. Uncovered: WebSocket upgrade refusals, central, and 4xx the
  gateway answers itself.

Counts per route and status:

```bash
jq -r '.line | fromjson | "\(.status) \(.route // ("(unmatched) " + .method + " " + .path))"' \
  ~/.equin/worktrees/<wt>/logs/http-refusals.jsonl | sort | uniq -c | sort -rn
```
