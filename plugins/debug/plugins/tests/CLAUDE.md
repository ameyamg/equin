# tests

Debug → Tests: every test file of this checkout with its last known status.
Design: `research/2026-11-11-global-test-status-page.md`.

## Verdicts are harvested, never run for the page

`./equin test` (framework/cli/test) digests the files it runs before the op
(`test/plugins/digest`) and, as the run's leader, writes one record per run to
the host-global `test-runs` dir. Every backend ingests that dir (`machine/`
`ingest.ts`: a watch, plus a catch-up pass after boot as the
`tests.ingest-catch-up` warm-up — after the tabs' restart replay; a pass skips opIds its database
already holds; a malformed record is reported once, an unknown `v` is left for
a newer reader). `./equin push` runs the tests its change affects through
the same command (`framework/cli/push/plugins/test-gate`), so its runs are
harvested like any other.

## Status = the results on the file's CURRENT digest

A result is keyed by (path, digest). The checkout's own digests
(`test_checkout_digests`) come from `./equin test-digest`, run as the
`tests.checkout-digests` supervised job, and the child answers `unchanged`
when the tree hash is the stored one:

- while the page is open: the `tests.digest-generation` value's
  `whileSubscribed` asks on subscribe and on every advance of main;
- on main, when its test runner is turned on (`plugins/idle-runner`, off by
  default): at every boot and advance, so main's verdicts follow its head.

The status rule is `deriveStatus` (core, pure); `recomputeFileStatus`
(server) is the ONLY writer of `test_file_status`, run after each ingested
record (its files) and each new digest set (the files whose digest moved, or
that came or went).

- **One row, one code.** The row's last result (`lastOutcome`, origin, op,
  cases, duration) is the newest result on the CURRENT digest — what the
  status is derived from — and only for a `stale` file the newest at any
  digest. Never a newer run of other code beside it (a row once read
  "failing" from main's run next to "passed" from an agent's run of its own
  change).
- **Own runs** (`ownPassed` / `ownFailed`): of the current-digest results,
  the ones this checkout's own runs recorded — `slug` = this backend's
  namespace, the one definition of "main's own run" (failing-report's judge
  uses the same). Main's runner selection reads them: one own failure is
  confirmed by ONE more run, and a failure only another checkout saw on this
  very code is verified here.
- An ingest pass that took in runs with failures emits `tests.runsIngested`
  (the runner's next selection).

- Not known yet is a state: until the first digests land the page shows the
  computing state, never an empty tree.
- `test_file_results` is capped to the newest 32 per file daily
  (`tests.results-cap`), never TTL'd: a stable file keeps its only verdict.
  The results on the file's current digest are kept apart (up to 32 more):
  agents' runs of their own edits would otherwise push out the verdict on
  this checkout's code, the file would read `stale`, and main's runner would
  re-run code that never changed.

## Run now / Investigate

Run now / Run stale / Run all post `tests.run-now`, which starts the
`tests.run-now` supervised job: an ordinary `./equin test <paths…>` with
`EQUIN_TEST_ORIGIN=run-now`. Its verdicts arrive like any run's, through its
record. Progress is not shown per file (JUnit exists only at the end): the
toast says how many files were started. Investigate (failing / flaky only)
files a task about the `test-file` subject under the Tests category.
