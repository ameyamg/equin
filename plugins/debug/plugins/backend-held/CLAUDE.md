# backend-held

A connection that **keeps a backend up for nobody** is a report. The gateway's idle sweeper never stops a backend with an open
connection. On 2026-11-27 five promo-film composition backends stayed up 5+
hours (one for two days), each on one connection, with no request completed
since. The gateway could say only `activeConns: 1`, not what that connection
was.

## Who files it, and when

`gateway/connections_report.go`, on the idle sweeper's tick. Every connection
the gateway proxies is a record (`gateway/connections.go`): HTTP or
WebSocket, method, host, path (never the query), User-Agent, Origin,
Sec-Fetch-*, principal, remote address, open time, bytes each way and the
last byte's time. `GET /gateway/connections[?worktree=<name>]` lists them
(owner-only).

The rule coverTwo rules, each filing one entry per connection, once. Neither applies to an
always-on backend (central, main) or the public namespace.

- **`silent`** (any kind): no request completed on the backend for **1 h**,
  and no byte either way on the connection for as long.
  - An HTTP request open that long with no body or response byte is stuck. A
    streaming response writes as it goes, so it never matches.
  - A live WebSocket moves bytes every couple of minutes: Bun pings it (120 s
    idle timeout) and the live-state client heartbeats every 20 s. An hour of
    silence means its peer is gone or frozen.
  - One hour is six idle timeouts (10 min) and thirty ping intervals.
- **`kept-alive`** (WebSocket): no request completed for **6 h**, and a
  WebSocket on the backend open as long, whatever its traffic.
  - A leaked automated browser answers pings and heartbeats exactly like a tab
    in use, so silence cannot catch it. Only time and identity separate them:
    the entry names the User-Agent and the remote address.
  - Six hours with not one request outlasts any working session on a page: it
    is a forgotten tab or a leaked browser.
  - In the 2026-11-27 incident, the backends were held 5+ h, and one for 2
    days.

**Fingerprint** `backend-held:<reason>:<kind>:<method> <path>`: the same
stuck client on several backends is one row.

guage contract

`gateway/testdata/backend-held-entry.json` is the entry the Go writer builds
(its test asserts exactly that). `core/kind.test.ts` parses that same entry
with the outbox envelope and this kind's strict schema.

**Takes effect on a gateway restart**: main's deploy hands the gateway over
once the change lands (`gateway/CLAUDE.md` § "The gateway follows main").

Literals `backend-held` (the kind, the Go `backendHeldKind`) and the
fingerprint are persisted. Do not rename them.
