# row-actions

## What this plugin owns

**Which** actions a JSONL transcript row carries — never how they look or reveal:

- **`JsonlRowActions.Item`** — the slot every row action contributes to (timestamp,
  copy, rewind / fork, raw JSON, text toggles, …). Its id string is
  `"conversation.jsonl-viewer.row-action"` and must stay byte-for-byte stable:
  persisted reorder directives are keyed on it, so renaming the slot silently drops
  every user's saved action order. Which actions sit on the row and which fold
  behind its ⋯ is the slot's config (`config/…/row-actions/item.jsonc`, an
  `overflow` node), not code.
- **`EventActionProvider` / `EventRowActions`** — the per-event context published once
  by `EventRow`, and the strip that reads it and renders the contributions.
- **`rowAction(action)`** — the ONE place an action gets a look. Every
  `button` action is drawn as the same `IconButton`; the `primitives/row-actions`
  cluster sizes it (xs) and tones it (muted at rest, foreground on hover), and
  behind the ⋯ it becomes a labelled row. A `time` action is the relative
  timestamp.

**An action is data, never a button.** A contribution's component reads what it
needs and returns `rowAction(action)` — `action` is `{ kind: "button", icon,
label, active?, disabled?, onClick?, popup? }`, `{ kind: "time", at }` or `null`.
Its return type is `RowActionElement`, a brand only `rowAction` mints, so a
component returning its own `<button>` / `<Button>` is a **tsc error**: no
contributor can give its action a size or colour of its own. This replaced a
free `component` slot where copy / investigate / change-answers drew a
hand-rolled `size-5` muted button next to `IconButton`s that inherited the prose
colour — the strip read as four different weights. An action that opens
something (a popover, a menu, a launch popover) passes `popup: (trigger) =>
<YourPopup trigger={trigger}/>`: the button is handed to you, the popup is yours.

Why a component and not a `useAction` hook field: the React Compiler refuses a
hook carried as a value (`react-compiler:no-silent-skips`), so the contribution
stays a component calling fixed hooks, and the brand does the enforcing.

**Placement is always in the flow, never over the content.** Card renderers put
the strip in their header's trailing slot; the headerless text/image renderers
render `<EventRowActions float />` FIRST inside their text, so the prose wraps
around it (a floating overlay hid the words under it).

The cluster itself is not ours: `EventRowActions` is a thin wrapper over
`primitives/row-actions` — the one row-action implementation in the app, which owns
the reveal, the click/pointerdown guards, the popup-hold and the control size, and
which `EventRow` anchors with its `rowActionsAnchor`. Buttons stay dumb: never
re-apply a reveal on an action. The domain name is deliberate — that primitive
exports a `RowActions` too, so don't rename this one back.

## Why it is a separate plugin

It sits **below `collapsible-card`** in the import graph, on purpose.

`collapsible-card` hosts `<EventRowActions/>` in its header. When the strip lived in
`jsonl-viewer/web`, that made `jsonl-viewer/web ⇄ collapsible-card/web` a cycle — and
the practical cost was that jsonl-viewer's own fallback row could not use
`CollapsibleCard` at all, so it stayed a dead one-liner. Extracting the strip breaks
the cycle and lets any card, including jsonl-viewer's own fallbacks, carry it:

```
jsonl-viewer/web ──► collapsible-card/web ──► row-actions/web
       └──────────────────────────────────────────┘
```

**This plugin must never import `jsonl-viewer/web`.** That single edge recreates the
cycle. Its dependencies are deliberately minimal — `transcript-watcher/core` for the
`JsonlEvent` type, `slot-render/web`, `primitives/row-actions/web`,
`copy-to-clipboard/web`, `icon-button/web`, `relative-time/web` — and there is no reason for that set to grow: an action that
needs jsonl-viewer state reads it from its own contributing plugin, not from here.

## Contributing an action

Contribute from the plugin that owns the behaviour, never by editing this one:

```ts
JsonlRowActions.Item({ id: "copy-tool-result", component: CopyToolResultAction })

export function CopyToolResultAction({ event }: { event: JsonlEvent }) {
  return rowAction(
    useCopyAction(event.kind === "tool-call" ? event.result?.content ?? null : null, "Copy result"),
  );
}
```

The component returns `rowAction(null)` (or `null`) when it does not apply to
that event kind — that is the standard gate, not a filter on the slot. Call your
own hooks before the gate. A copy action is `useCopyAction(text | null, label)`.
